The work

Google Identity Architecture is an outside-view specification by Lee Sharks.

The paper uses confidence labels:

- DOC — official Google documentation; - PUB — public technical, legal, patent, or academic material; - LEAK — fields or claims associated with the 2024 API Content Warehouse leak; - OBS — archive observations; - INF — inference; - SPEC — terminology or architecture introduced by the paper.

Five interacting graphs are proposed.

1. User Graph: account, browser, device, activity, location, and personalization state. 2. Session Graph: interface, experiment bucket, previous turns, cookies, region, rollout state, and query fan-out. 3. Entity Graph: candidate entities and clusters resolving strings into people, works, organizations, or concepts. 4. Source Graph: pages, domains, publishers, authors, structured data, trust, authority, and extractability. 5. Composition Graph: the documents and claims admitted into a generated answer and rendered source window.

The central claim is:

> Organic retrieval success is not the same as composition admission success.

The paper names Entity-Level Compositional Suppression as the condition in which the organic layer resolves correctly while the generated answer substitutes, excludes, or weakens the target entity.

The Session Graph matters because a visible query may branch into multiple hidden subqueries. Different branches can activate different entity neighborhoods and support sets.

The specification also treats incognito browsing as a local browser-state reset rather than identity null and proposes capture metadata for account state, browser, device, network, region, previous queries, interface, source window, and organic results.

The Secret Name Armature is offered as a counter-architecture: names are treated as signed, provenance-bearing routing bodies rather than opaque admission clusters.
