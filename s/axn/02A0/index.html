The work

The SIM Protocol v1.0 defines typed semantic-integrity assertions for canonical web surfaces.

Schema.org can express ordinary relations such as author, work, and organization. SIM is designed for claims such as:

- this entity is a particular type; - this entity is not a commonly confused type; - this entity is distinct from a named neighbor; - a phrase has a declared provenance; - no affiliation exists with a specified organization; - this version supersedes an earlier deposit; - a named heteronym authored the object; - a compression-survival summary should be preserved; - a specific URL and DOI anchor the assertion.

The v1.0 tag set includes:

- `spxi:isType` - `spxi:isNotType` - `spxi:distinctFrom` - `spxi:phraseProvenance` - `spxi:notAffiliatedWith` - `spxi:supersedes` - `spxi:authoringHeteronym` - `spxi:compressionSurvivalSummary` - `spxi:canonicalURL` - `spxi:licenseDeclaration` - `spxi:institutionalAffiliation` - `spxi:depositAnchor`

Deployment proceeds by identifying the boundary failures, typing each assertion, placing the same claims in page-head metadata and JSON-LD, depositing the inscription, and cross-referencing the governing SPXI deployment.

SIM claims must be falsifiable. “Distinct from X” performs the protocol; “unique and important” does not.

The specification names four major failure modes:

- conflicting assertions across pages; - missing persistent anchor; - aspirational rather than falsifiable language; - marker proliferation without a coherent compression-survival kernel.

Within the Restored Academy registry, SIM is a dependency of SPXI and supports Holographic Kernel inscription and CDI measurement.
