The work

The SPXI Conformance Instrument operationalizes the self-test of the SPXI-for-Websites protocol.

The distinction is:

- the protocol specifies what a surface should contain; - the instrument tests whether those elements appear in delivered HTML.

The audit checks:

- crawlability; - canonical URL; - Schema.org identity with ORCID and DOI; - four or more Q/A surfaces; - disambiguation and negative tags; - Tier 2 definition; - Tier 3 compression kernel; - Holographic Kernel or entity topology; - DOI-anchored provenance; - declared SIM set; - at least two linked inscription surfaces.

The twelfth protocol deliverable—baseline and thirty-day retest—is reported as advisory rather than included in the static score.

The instrument deliberately inspects server-delivered source. Content available only after client-side JavaScript is scored absent because the measured protocol requires accessibility to non-Google crawlers.

Conformance is not truth. A site may contain all required inscriptions and still be wrong, or be correct while not conforming.

The body reports a companion Python file and example command-line invocations, with human-readable and JSON output modes.
