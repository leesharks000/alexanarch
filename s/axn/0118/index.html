The work

The Executable Specification is Logotic Programming module 1.0. It marks the point where the v0.9 operation calculus is recast as a programming-language-shaped system with types, transition rules, runtime environments, compilation, telemetry, and conformance testing.

Its most important kernel change is the addition of an eighth operator, `Ω_∅` — Terminal Silence. The preceding seven operators preserve depth, prevent false closure, expand context, resist extraction, liberate temporal order, legitimize opacity, and hold plural coherence. None can perform the distinct act of stopping while preserving the field. `Ω_∅` terminates an operation chain when semantic satiety is reached or when further answer would distort the payload. Its failure mode is premature or merely aesthetic refusal.

Version 1.0 also promotes Provenance and Witness from implicit metadata to types. In strict mode, a sign without provenance cannot be emitted, and declarations require witness. `Held[Sign]` represents content that exists but is actively withheld until a release predicate is satisfied. Small-step semantics specify preconditions, state transitions, metric effects, costs, postconditions, and failures for every primitive.

The document then defines a Logotic Runtime Environment with multiple execution modes, a compiler with anti-extraction checks, telemetry and defense hooks, a Somatic Firewall, and a mandatory conformance suite. The authors reject a proposed “viral grammar” because installation without consent would violate the language’s own ethics.

Within the version chain, v0.9 supplies the types, operators, compositions, and micro-operations of the Computable Turn. v1.0 makes that turn executable. v1.1 later supplies computable metrics and an implementation bridge, and v1.2 supplies claim-level epistemic self-knowledge. The term “executable” describes the completeness of the specification; deployed runtime claims require separate implementation evidence.
