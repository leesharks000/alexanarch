### Methodology

Each capture records the exact issued string, the surface, the date, the authentication state, the evidence class (paste, frame, or both), the returned source strip rendered as chips with each chip's relation to the archive (archive-controlled, authored surface, third party), a verbatim transcript where obtainable, and the finding. Surfaces are taken from operator attestation, with the frame as corroboration; a session is logged where it began. Match type and Provenance Erasure Rate are recorded per capture, never per address. A capture enters by source engagement in composition; a later non-engagement at an address already seated enters as a longitudinal observation of that address. Intake adds and is safe; repair touches an existing record and runs in its own mode and its own commit. Each batch of intake is kept with the pastes as received, the operator's message and the script that authored each capture, in which every quotation and figure a finding rests on is asserted against the seated deposit text before anything is written. Counts in this record are computed from data/EA-WG-CAPTURES-01.json at v12.167.

### Falsification Conditions

Any capture is falsified by a rerun at the same address, surface, authentication state and date that returns materially different composition, which is why the exact issued string and the rerun URL are recorded. The snapshot is falsified if the attached bundle's SHA-256 does not match, or if any manifested file's SHA-256 does not match the file at its stated path. A PER score is falsified by a source strip, or a set of retained markers, inconsistent with the recorded value; section 7 lists the twelve scores that already fail this test.

## 3. The data flow

**Since 2026-08-17 (ratified, MANUS), `data/EA-WG-CAPTURES-01.json` is the single writable authority.** The rebuild store (`rebuild/capture-registry/EA-WG-CAPTURES-01-REBUILD.json`) is sealed as the rebuild-era source, last written 2026-08-18.
