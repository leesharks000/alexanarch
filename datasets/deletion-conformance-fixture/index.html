Deletion Semantics Conformance Fixture

A known-bad identifier corpus for testing deletion, tombstone, presence, and successor semantics.
Version 2.1 · 2026-08-26 · Dataset CC0 1.0 · Scripts MIT · Offered to knowledge-catalog #207

117 cases across 17 classes, drawn from a real deletion event (2026-06-19) and its aftermath. Every case carries subject-explicit ratified axes — validity / presence (sparse: removed | never_landed | no marker) / edges — an axis_subject naming what each axis value is about, a reason object where not_disclosed and unknown are first-class, and machine-readable expected blocks so an implementation can pass or fail. Validity is never derived from identifier survival.

v2.2 · 2026-08-26. Six cases added after the cross-implementation test found that v2.1 — one never_landed case in 111 — barely exercised the distinction it helped uncover. The additions are a matched A/B/C trio with B split by whether the removal is exposed on a machine-readable discovery surface, plus the intake-acknowledgment pair. v2.2 is the first discriminating cut against the current reference implementation: the unrepaired reference consumer fails the fixture, and a repaired consumer differing by one absence-record lookup passes it: reference_verdict.py scores 2 false positives unrepaired and 0 repaired, the difference being one lookup. v2.1 is retained as cases-v2.1.json.
Conformance testing is offline by default against the committed cases.json: run python3 verify_offline.py (no network). Live re-probing is optional (reprobe_live.py), emits dated observation reports, and never mutates expected results. The fixture is frozen by manifest.json (SHA-256 per file + source commit).
